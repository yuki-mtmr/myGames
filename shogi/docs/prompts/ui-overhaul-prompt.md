## 画面フローの要件(将棋ユーザーの期待に合わせる)

### 1. 終局フロー(最優先)
- 終局時に**モーダルで盤面を覆わない**。結果は盤面上部の小さなバナー
  (勝敗+理由)で示し、盤面はそのまま見える
- 終局後、**自動で検討モードに移行**する(将棋クエスト方式):
  - 棋譜ナビゲーション: |◀ 先頭 / ◀ 1手戻る / ▶ 1手進む / ▶| 末尾。
    キーボード ←→ 対応。棋譜リストのクリックでその局面へジャンプ
  - 局面の並べ直しは `sfenHistory`(全局面の SFEN 列が既にある)から
    `SfenConverter.sfenToBoard` で復元して描画するだけ。ShogiGame の
    対局状態は変更しない(読み取り専用の viewer として実装)
- 「AI解析」実行後:
  - **評価値グラフ**(手数 × 先手視点評価値。`GameAnalyzer` の evals を
    そのまま使う。SVG or canvas、ライブラリ不要)を棋譜の上に表示
  - グラフクリック/棋譜クリックでその局面へジャンプ
  - 悪手(?!/?/??)は棋譜リストとグラフ上にマーカー表示(橙/赤/濃赤)
  - 悪手クリック → 既存の再演モード(`src/ui/ReplayMode.js`)へ
- 「新しい対局」はバナー内ボタン+ヘッダに常設(誤タップしない位置)

### 2. 対局画面
docs/ux-spec.md の規約に準拠:
- 盤は中央、自分の駒台は右下(手前)・相手は左上(奥)、手番表示、
  最終手ハイライト、移動可能マス表示(設定 OFF 可)、成り確認
- 評価値バーは縦バー(先手+で下から伸びる)、Mate 時は「+詰N」表記
- 情報密度を抑える: 待った/保存/棋譜出力等は⋯メニューか下部に格納し、
  対局中の主画面は 盤・駒台・時計・評価値バー だけにする

### 3. デザイン
- グラスモーフィズムをやめ、**将棋アプリの definitive な見た目**に寄せる:
  木目調の盤(手続き生成でよい)、くっきりした駒文字、和風の落ち着いた
  配色(生成 UI 感のあるグラデーション・過剰な角丸・blur を排除)
- ライト/ダーク両テーマで成立させる(CSS Variables は既存の仕組みを流用)
- モバイル(375px)で盤が画面幅いっぱいに収まるレスポンシブ

## 制約
- UI の視覚調整は TDD opt-out(スクリーンショット検証で代替)。ただし
  検討モードの局面復元ロジック(sfen インデックス管理)は純粋関数に
  切り出して vitest でテストする
- 既存テスト 138 件を green のまま保つこと(`npm test`)
- 閾値・色・寸法のマジックナンバーは config / CSS Variables に集約
- 各フェーズ完了時に Playwright で実機フロー検証+スクリーンショットを
  撮り、将棋ウォーズのスクショと並べて自己採点してから次へ進む

## フェーズ分割の推奨
1. ui-principles.md + verify:ui パイプライン(採点基盤を先に作る)
2. 終局フロー+検討モード(棋譜ナビ・局面復元)
3. 評価値グラフ+悪手マーカー統合
4. 対局画面のデザイン刷新(盤・駒・駒台・評価値バー)
5. 全画面の統一(感想戦/ダッシュボード/ドリルを新デザインに揃える)
